## 一、研究设计总体架构

一篇完整的 staggered DID 研究设计包含九个模块：

1. **研究假设（H1-H4）**：主效应 + 双机制 + 异质性，每个假设带明确预期符号
2. **被解释变量构造**：两阶段构造法（p-j-t 层面 β）+ 多版本交叉验证
3. **处理变量构造**：多级递进（binary → 级别 → 性质 → 连续强度）
4. **实证策略**：主回归 + 处理强度递进 + 事件研究（含升格二次冲击）
5. **内生性检验**：反向因果、遗漏变量、工具变量、Leave-one-out
6. **稳健性矩阵**：六维度 26 项
7. **异质性分析**：产权、政治关联、处理强度、市场化、行业、制度基础
8. **进一步研究**：经济后果、地级市拓展、行为改变、外溢效应
9. **数据审计**：逐项对照设计检查 working data，排优先级

## 二、被解释变量构造：三种方案

### ⚠ 前置检查一：聚合单元样本量

**任何两阶段设计跑之前，必须先查 p-j-t 单元内企业数分布。** 论文1 的教训：31 省 × ~20 行业 × 9 年 = 3,051 个 p-j-t 单元，中位数只有 3 家企业/单元，65% 的单元不足 5 家——两阶段 β 在 p-j-t 层面根本不可行。升到省-年（p-t）层面后每个单元中位数 40 家，但即便如此，β 估计仍因极端值而不稳定。

**检查方法**：
```stata
egen pjt = group(prov_id ind_id year)
collapse (count) n = subsidy_rd_v1, by(pjt prov_id ind_id year)
summarize n, detail
count if n < 5
```
若超过 30% 的单元不足 5 个观测，该粒度放弃两阶段。

### ⚠ 前置检查二：构造出的 DV 分布

**构造完 β 后，必须检查分布再决定是否可用。** 论文1 的教训：level-log 形式（`subsidy ~ ln(R&D)`）构造出的 β_pt 偏度 3.90（严重右偏），标准差（315 万）超过均值（260 万），取值范围 -39 万到 3080 万。原因是补贴金额极端值主导回归斜率——重庆 2016 年一家企业拿到巨额补贴，把整个省-年的 β 拽飞。这种 β 作为第二阶段被解释变量时，任意一个异常单元就能拽跑 DID 估计。

**解决方案：log-log 变换**。改用 `ln(subsidy + 1) = α + β × ln(R&D)` 后，偏度从 3.90 降至 0.03（近乎完美对称），标准差 0.78，β 成为无量纲弹性。对数变换压缩了补贴金额的极端值——1 亿和 100 万在 log 尺度下差距远小于原始尺度。

**检查方法**：
```stata
* 构造 β 之后
summarize beta_pt, detail
* 红线：偏度绝对值 > 2，或标准差/均值 > 1.5 → 变换函数形式
* 红线：负值超过 10% → 检查单元内是否有大量零补贴企业
```

**函数形式的决断顺序**：
1. 默认先试 log-log（弹性，最稳定）
2. 若 log 变换后仍有严重偏度 → 考虑去掉极端单元或用中位数回归替代 OLS
3. level-log 和 level-level 仅作为最后手段，且必须附有极端值处理方案

### 方案 A：两阶段 β（仅当单元样本量充足 + DV 分布可用）

第一步（聚合单元内截面回归）：
```
ln(subsidy_rd_i + 1) = α_cell + β_cell × ln(R&D_i,t-1) + ε_i
```
第二步：
```
β_cell = α + γ × BigData + Controls + FE + ε
```
第二阶段按单元企业数加权（WLS）。优势：主回归 γ 不含交互项。劣势：β 对离群值敏感，样本量不足时信噪比极低。

### 方案 B：企业层面交互项（推荐为默认方案）

```
ln(SubsidyRD+1)_it = α + β₁·ln(R&D)_i,t-1 + β₂·post_pt + β₃·ln(R&D)_i,t-1 × post_pt + Controls + FE
```
β₃ 就是配置效率变化。这是领域内标准做法（金友良等 2025 即用此结构）。

**关于「主回归不能只有交互项」**：论文可以先展示 `ln(Subsidy+1) ~ post + FE`（主效应：大数据局→补贴总量），再展示加入交互项的完整模型。两个结果并列，第一个是主效应，第二个才是配置效率。审稿人不会认为你只有交互项。

### 方案 C：简单比率（快速验证用）

```
ratio_pt = Σsubsidy_rd / Σrd_spending   （省-年层面总补贴/总研发）
```
不需要回归自由度，任意大小单元都能算。适合初步探索，不适合正式论文主回归。

### 决断规则

1. 先查单元样本量（方案 A 的前提条件）
2. 若 p-j-t 单元足够大 → 方案 A 为主，方案 B 为稳健性
3. 若单元太小 → 方案 B 为主回归，方案 A 放弃
4. 方案 C 仅用于数据探索阶段快速判断是否有信号
5. **无论选哪个方案，先用实际数据构造 DV 并检查分布**——不要纸上画模型

## 三、处理变量的多级递进

单一 binary DID 说服力不足。利用级别和性质的差异构造剂量-反应。

| 层级 | 变量 | 回答 |
|------|------|------|
| L1 | post (0/1) | 有没有？ |
| L2 | d_zhengting | 强不强？ |
| L3 | d_admin_gov | 实不实？ |
| L4 | treat_score1 (0-5) | 有剂量-反应吗？ |

若 L1-L4 方向一致且幅度递增，遗漏变量必须同时与成立时间、级别、性质三个维度相关——概率极低。

经历过升格/转性的省份提供天然的「处理加剧」事件，可在事件研究法中检验二次跃升。

## 四、被解释变量的多源交叉验证

用完全独立的数据生成过程构造同一指标的多版本。

| 版本 | 来源 | 定位 |
|------|------|------|
| V1 | 主数据源，标准规则 | 主回归 |
| V2 | 同一数据源，收紧规则 | 排除边界争议 |
| V3 | 正交数据源，不同识别过程 | 排除数据供应商依赖 |
| V1∩V3 | 两源同时确认 | 高置信度子样本 |

所有版本结论一致 → 结论不依赖特定识别规则或数据供应商。

## 五、双机制对称设计

单一机制容易被质疑「故事不完整」。双机制从不同方向指向同一结论，理论上对称。

**本文的两条机制**：

| 机制 | 名称 | 检验方式 | 预期 |
|------|------|---------|------|
| 机制一 | 关系渠道压缩 | 企业层面：PC × post → 补贴 | β₃ < 0 |
| 机制二 | 信息渠道强化 | p-j-t 层面：分 SuspectRD 组构造 β，比较 γ^C vs γ^S | γ^C > γ^S |

**对称性**：关系渠道让企业靠「谁认识你」拿补贴，信息操纵让企业靠「把数字做好看」拿补贴。大数据局堵住了这两条路。

**设计要点**：
- 两个机制使用不同层面的数据（企业层面 vs p-j-t 分组 β）
- 依赖不同关键变量（PC vs SuspectRD），不共享识别变异
- 预期方向不同但指向同一结论

## 六、内生性检验标配

1. **反向因果**：成立前 β 趋势不预测成立概率
2. **遗漏变量**：GDP×时间趋势 + 省份线性趋势 + 初始水平分组
3. **省级领导特征**：控制省委书记/省长任期、年龄、换届
4. **工具变量**：同级压力（同区域其他省份成立比例，不含本省）
5. **排除驱动**：Leave-one-out + 排除特殊省份

## 七、Falsification Test

选「理论上不应受影响的因变量」做安慰剂检验。本文用非研发类补贴（稳岗补贴、出口补贴）——缺乏可交叉验证的客观指标，大数据局不应提升其配置效率。

如果只有研发补贴变准了、非研发补贴没变，排除「同期所有补贴都在变准」和「大数据局只是象征性改革」。

## 八、数据审计流程

开始实证分析前，逐项对照设计检查 working data：

1. 列出每个模块需要的变量
2. 确认哪些已有、哪些需外部合并
3. 对已有变量做质量检查（缺失率、异常值）
4. 对缺失变量按优先级排序：主回归必需 > 稳健性 > 进一步研究
5. 检查 province scope（排除非境内实体）和 year range（按设计截取）

详见 `references/data-audit-checklist.md`。

## 九、避免的设计陷阱

1. 不要同时做「TFP→补贴」和「补贴→TFP」——内生性互相污染
2. 不要用「企业不知道有补贴」作为机制——上市公司有 IR 部门
3. 不要用「过去有关系就拿补贴」作为机制——既危险又不可证伪
4. 不要提「两个竞争性渠道」——一条故事线
5. 不要用政务平台上线代理数据打通——平台捕获服务可得性，不是后端能力
6. 不要只有交互项当主回归——但可以用「主效应 + 交互项」并列的方式展示，审稿人接受
7. 不要只有一个机制——尤其是单一机制与主回归高度重叠时
8. 不要用单一 binary 做处理变量——如果数据支持多维刻画，用它
9. **不要在不检查单元样本量的情况下承诺两阶段设计**——论文1 的 β_pjt 在 p-j-t 层面因 65% 单元<5 家企业而不可行，被迫降级到企业层交互项。任何聚合指标构造前必须跑 cell size check
10. **不要用 level-log 构造 β 当被解释变量**——论文1 的教训：补贴金额极端值主导回归斜率，构造出的 β 偏度 3.90，标准差超过均值，完全不可用。默认用 log-log（ln 补贴 ~ ln 研发），构造后必须检查偏度和标准差
